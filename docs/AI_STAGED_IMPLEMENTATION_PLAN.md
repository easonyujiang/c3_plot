# C3-Mass 分阶段 AI 实施计划

## 使用方法

不要一次性把整份文档交给执行 AI。

每次只复制一个阶段的 Prompt。当前阶段通过验收后，再交付下一阶段。若执行 AI 发现范围外的问题，只允许记录到阶段报告中，不得顺手重构其他模块。

建议顺序：

1. 基线审查
2. 多次点火数据模型
3. 逐级燃烧求解器
4. 轨道任务后端接入
5. 任务结果前端接入
6. `.craft` 解析增强
7. 批量导入与一致性
8. 数据可信度与发布验收

---

## 阶段 1：建立可信基线

### 目标

只审查，不修改业务代码。确认当前系统的真实状态，为后续工作建立基线。

### 交给 AI 的 Prompt

```text
请审查 E:\Create\Code\c3_plot 项目。本阶段只允许读取文件、运行非破坏性检查和编写一份审查文档，不得修改业务代码、数据库或用户数据。

重点确认：

1. 火箭级序和 stage_index 的定义，哪一个索引代表末级。
2. YAML 写入 SQL、SQL 导出 YAML、编辑器保存和批量导入的完整路径。
3. compute_rocket、compute_orbit_mission、find_rockets_for_orbit 的调用关系。
4. multi_ignition 当前在哪里产生、保存和使用。
5. .craft、.loadmeta、SSTU 多发动机的当前支持程度。
6. 现有测试覆盖了什么，没有覆盖什么。
7. 当前数据库迁移状态和可能的兼容问题。

在 docs/PROJECT_BASELINE_AUDIT.md 中输出：

- 当前架构图或模块清单。
- 已确认的数据流。
- 按 P0/P1/P2 排序的问题。
- 后续阶段不能破坏的兼容约束。
- 阶段 2 所需的最小接口建议。

验收要求：

- 不修改业务代码。
- 不修改或删除现有数据库。
- 运行现有测试并记录真实结果。
- 所有判断必须附文件和函数位置。
- 完成后停止，不实施任何修复。
```

### 验收

- 生成 `docs/PROJECT_BASELINE_AUDIT.md`。
- 现有功能和数据零变化。
- 文档能够明确回答“末级到底是哪一级”和“多次点火标志来自哪里”。

## 阶段 2：定义多次点火数据模型

### 目标

只建立任务燃烧序列和执行结果的数据结构，不接入网页，不重写轨道算法。

### 交给 AI 的 Prompt

```text
请在 E:\Create\Code\c3_plot 中完成“多次点火任务数据模型”。

开始前先阅读 docs/PROJECT_BASELINE_AUDIT.md。

本阶段只处理纯 Python 数据结构和测试，不修改前端，不增强 .craft 导入，不修改现有 API 返回结构。

需要定义：

1. BurnRequirement：一次任务燃烧的目标。
2. StageState：某一级在某一时刻的质量、推进剂、点火状态。
3. BurnResult：一次燃烧的实际结果。
4. MissionSimulationResult：完整任务的成功状态和失败原因。

字段至少覆盖（分布在各结构中，注意职责边界）：

- 燃烧名称和顺序（BurnRequirement.burn_id / order / name）。
- 目标 Δv（BurnRequirement.target_dv_m_s）。
- 执行级（BurnResult.stage_index）。
- 燃烧前后质量（BurnResult.mass_before_t / mass_after_t）。
- 消耗和剩余推进剂（BurnResult.propellant_consumed_t / propellant_remaining_t）。
- 是否为首次点火（BurnResult.ignition_kind：first / restart / unassigned，由求解器判定）。
- 是否需要重启、是否允许重启（StageState.multi_ignition + ignition_count，由求解器结合任务燃烧序列判定；**不得预先写进 BurnRequirement**）。
- 是否满足目标、失败代码和中文说明（BurnResult.success / failure_code / failure_reason_zh；MissionSimulationResult 汇总）。
- 数据质量状态（DataQuality：exact / estimated / insufficient）。

要求：

- 放在独立模块中，不与 Flask、SQLite 或 DOM 耦合。
- 兼容普通 dict 输入和 JSON 序列化。
- 不重复实现火箭方程。
- 不修改 compute_orbit_mission 现有结果。
- 不引入不必要的新依赖。

测试至少覆盖：

- 数据结构可以正常创建和序列化。
- 首次点火与重启可以区分。
- 失败代码稳定。
- 输入数据不会被原地修改。

完成后更新一份简短的数据契约文档。运行全部测试并报告结果，然后停止。
```

### 验收

- 只有数据模型、测试和契约文档发生变化。
- 现有 API 和网页没有变化。

## 阶段 3：实现逐级燃烧求解器

### 目标

用火箭方程逐次扣除推进剂，判断每一次点火是否能够完成。

### 交给 AI 的 Prompt

```text
请在 E:\Create\Code\c3_plot 中实现纯 Python 的逐级、多次点火燃烧求解器。

开始前阅读：

- docs/PROJECT_BASELINE_AUDIT.md
- 阶段 2 生成的数据契约文档

本阶段只实现求解器和单元测试，不接入 Flask、SQLite、前端或 .craft 导入。

求解器需要：

1. 接收已经标准化的火箭级数据、载荷和 BurnRequirement 列表。
2. 每次燃烧使用火箭方程计算推进剂消耗。
3. 每次燃烧后更新该级剩余推进剂和整箭质量。
4. 禁止不同燃烧重复使用同一份推进剂。
5. 区分新一级首次点火和同一级重启。
6. 在不支持重启时返回稳定的失败代码。
7. 在推进剂不足时返回实际可提供 Δv 和短缺量。
8. 支持分级，但不得自动猜测无法从输入确定的分级时机。

这一阶段不要求模拟大气飞行、有限推力或燃烧时间。

测试至少覆盖：

- 同一级连续两次燃烧正确扣除推进剂。
- 不可重启级第二次点火失败。
- 新分离出的上面级首次点火不被误判为重启。
- 推进剂不足时正确失败。
- 多级火箭质量变化正确。
- 原始输入不被修改。

完成后运行全部测试并停止，不要接入现有运力查询。
```

### 验收

- 求解器是纯函数或近似纯函数。
- 有明确、稳定的失败原因。
- 现有网页和 API 未被改动。

## 阶段 4：接入轨道任务后端

### 目标

让任意轨道查询同时返回“快速估算”和“逐级验证”，但暂时不改前端布局。

### 交给 AI 的 Prompt

```text
请把已经完成的逐级燃烧求解器接入 E:\Create\Code\c3_plot 的轨道任务后端。

本阶段只修改计算层、服务端 API、必要测试和文档，不修改前端页面。

要求：

1. 保留现有校准曲线反插值，命名为快速估算结果。
2. 将 compute_orbit_mission 产生的燃烧序列转换为 BurnRequirement。
3. 对每枚候选火箭运行逐级燃烧验证。
4. API 同时返回：
   - 快速估算运力。
   - 逐级验证状态。
   - 每次燃烧执行级。
   - 剩余推进剂。
   - 重启需求。
   - 失败原因。
   - 数据质量状态。
5. 不得因为逐级数据不足而伪造结果；此时返回 data_insufficient。
6. 现有 API 字段保持兼容，只允许新增字段。
7. 推荐结果不能选择逐级验证明确失败的火箭。

重点验证 35786 km @ 180°圆轨道：

- 进入停泊轨道。
- 霍曼转移出发。
- 高点圆化与剩余平面变化。
- 三次燃烧中哪些属于同一级重启必须由级分配结果决定。

增加 API 和计算测试。完成后运行全部测试并停止，不修改前端。
```

### 验收

- 旧客户端仍可读取原字段。
- 新字段可以解释火箭为何可行或不可行。
- 结果不会只依赖 `multi_ignition` 布尔值。

## 阶段 5：接入任务结果前端

### 目标

把阶段 4 已经存在的结果清晰显示出来，不改动其他网站架构。

### 交给 AI 的 Prompt

```text
请在 E:\Create\Code\c3_plot 中完成逐级任务验证结果的前端展示。

本阶段只修改任意地球轨道查询相关的 HTML、CSS、JavaScript 和浏览器测试。不要改后端算法，不要重构导航、编辑器、图表或导入模块。

需要显示：

1. 快速估算运力与逐级验证状态。
2. 点火时间线。
3. 每次燃烧的执行级、目标 Δv、实际 Δv。
4. 燃烧前后质量与剩余推进剂。
5. 首次点火或重启。
6. 明确失败原因。
7. 数据不足和低置信度提示。
8. 火箭列表中的逐级可行状态。

保留 ISS、SSO、GTO、GEO 预设，并允许手动输入 35786 km @ 180°。

要求：

- 深浅色模式均可读。
- 移动端不出现严重横向溢出。
- 不使用浏览器 alert。
- 不破坏“查看火箭”跳转。
- 更新静态资源版本，避免旧缓存。

使用浏览器完成真实回归并记录结果。完成后停止。
```

### 验收

- 用户能直接看懂“哪一级在哪一次点火失败”。
- 前端没有改变计算结论。

## 阶段 6：增强 `.craft` 解析

### 目标

只提高单个 `.craft` 文件生成编辑草稿的准确度。

### 交给 AI 的 Prompt

```text
请增强 E:\Create\Code\c3_plot 的 .craft 半自动解析器。

用户允许只读访问：
D:\SteamLibrary\steamapps\common\Kerbal Space Program

本阶段只处理单文件解析、草稿生成、警告和测试。不要修改批量导入事务、任务仿真或网站整体架构。

优先支持：

1. PART 对称数量。
2. stage、istg、dstg 等级信息。
3. ModuleEngines 和 ModuleEnginesFX。
4. MultiModeEngine。
5. SSTU 单部件多发动机和发动机集群。
6. RESOURCE 和推进剂质量。
7. RealFuels / ModuleFuelTanks 的可识别字段。
8. 分离器、径向助推器和并联级。

不能可靠识别的内容必须进入 structured_warnings，包含：

- 部件或模块名称。
- 数量。
- 推测所属级。
- 未识别字段。
- 对湿质量、干质量、推力或比冲的潜在影响。

禁止静默忽略未知发动机和未知燃料数据。

使用项目 VAB 样例和 KSP 安装目录中的配置建立测试夹具。完成后运行测试并停止，不接着重构批量导入。
```

### 验收

- SSTU 多发动机不会被合并丢失。
- 未识别数据能够被用户看到。
- 导入完成后仍生成可编辑草稿。

## 阶段 7：批量导入与 SQL/YAML 一致性

### 目标

让大量新火箭能够安全、可恢复地进入数据库。

### 交给 AI 的 Prompt

```text
请完善 E:\Create\Code\c3_plot 的批量导入和 SQL/YAML 一致性机制。

本阶段不修改轨道算法和 .craft 解析规则，只使用现有解析结果。

实现：

1. 文件夹扫描和 craft/loadmeta 配对。
2. 文件哈希重复检测。
3. 同名火箭差异预览。
4. 新建、覆盖、跳过三种明确操作。
5. 单文件失败不影响其他文件。
6. SQL 与 YAML 写入失败时能够回滚。
7. 导入后生成逐文件报告。
8. 提供只读一致性检查接口或命令：
   - 仅 SQL 存在。
   - 仅 YAML 存在。
   - 内容不一致。
   - 两者一致。
9. 修复差异必须由用户选择方向，不得静默覆盖。

保持旧 YAML 和旧数据库兼容。不要删除用户文件。

增加事务、重复导入、部分失败和一致性测试。完成后运行测试与浏览器回归，然后停止。
```

### 验收

- 重复导入不会产生重复火箭。
- SQL/YAML 任一侧失败不会留下半条数据。
- 用户能够审计每个文件发生了什么。

## 阶段 8：数据可信度与发布验收

### 目标

补齐来源、置信度和完整回归，使项目达到稳定日常使用状态。

### 交给 AI 的 Prompt

```text
请完成 E:\Create\Code\c3_plot 的数据可信度和发布验收阶段。

本阶段不得大规模重构计算算法或页面架构。

为火箭和关键数据增加：

- 来源文件。
- 导入时间。
- 最后修改时间。
- KSP/RSS/RO版本。
- 模组列表。
- 校准点来源。
- 人工确认状态。
- 数据置信度。

前端需要在火箭详情和任务结果中显示简洁的数据质量摘要。

随后建立完整回归清单，覆盖：

- Neutron I 2630 显示和导航。
- 图表缩放。
- 全开/全关。
- 深浅色输入框。
- 任务自动分配。
- ISS、SSO、GTO、GEO查询。
- 35786 km @ 180°查询。
- 多次点火失败原因。
- YAML导入。
- craft导入和自动进入编辑页。
- 文件夹批量导入。
- SQL/YAML一致性。

修复本阶段回归中发现的明确缺陷，但不要顺便增加新功能。

最终更新 README 和 docs，给出：

- 一键运行方式。
- 数据备份方式。
- 模型适用范围。
- 已知限制。
- 测试结果。

完成后停止，并按严重程度列出仍未解决的问题。
```

### 验收

- 核心流程均有自动化或浏览器回归记录。
- 用户能够判断一条运力结果是否值得信任。
- README 足以让新用户启动和备份项目。

## 当前推荐动作

现在只执行“阶段 1：建立可信基线”。

阶段 1 不改代码，风险最低，而且能够防止后续 AI 对级序、数据同步或现有兼容性作出错误假设。
