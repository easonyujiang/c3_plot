## 当前目录职责

`c3_mass/` 存放计算模型；`server/` 存放 API、持久化和游戏配置读取。实际安装发动机解析归入 `server/installed_engine_audit.py`。

工具通过 `python -m` 调用：`tools.data`、`tools.plot_capacity` 是日常入口，`tools/game/` 是游戏、遥测与基线证据工具，`tools/research/` 是质量和源码研究，`tools/release/` 是发布，`tools/dev/` 是开发验证服务。共享路径位于 `tools/paths.py`。

插件 C# 源码集中于 `game_plugin/`，构建和只读 API 检查入口位于 `tools/game/`。插件输出为 `output/plugins/`，发布包为 `output/releases/<版本>/`，不再绑定某次验收日期。

文档按 `models/`、`ksp/`、`validation/`、`evidence/` 分类。根目录只保留应用启动、测试、项目说明与必要配置。

## 数据与证据保留规则

- `c3_plot.db`、`rockets/`、`output/`、`backups/`：本地业务数据，由用户操作产生，不随 Git 提交。
- `VAB/`、`engines/`、`experiments/`：不再作为项目副本保留；真实输入从 `C3_MASS_KSP_ROOT` 读取。
- 全部 SQL 迁移：旧数据库升级需要按序执行，不能删除。
- `tests/fixtures/`：仍是代码内最小算法输入和解析器规范数据，不是游戏样例。
- `docs/evidence/<folder>/`：显式冻结、带 `manifest.json` 哈希清单的飞行证据；不参与启动导入。
- 历史实验、固定火箭 YAML 和旧输出不恢复为当前基线；如需追溯，从 Git 历史或本机游戏目录读取。

## 验证方式

从根目录运行 `python run_tests.py`；它隔离数据库、YAML 与输出，单次测试遗留的临时文件也在该轮临时根目录中清理。

前端执行 `npm ci`、`npm run build`，然后针对隔离服务运行 `npm run check:ui`。发布验证需解压运行包、核对清单，并用全新数据库访问首页、资源和任务 API。详见 [工具入口](../tools/README.md)。

正式发布要求干净工作区与匹配版本标签。2026-10-24 创建 `v0.2.0` 标签并指向当时的 HEAD；原有 `v0.1.0` 标签未移动。
