# 后续改进计划

检查日期：2026-10-21。本轮已保留现有 Git 基线，将 9 个计算与任务模块迁入 `c3_mass/`，同步调整调用、资源路径与发布打包规则。本文件记录建议，以下功能尚未实施。

本轮验证：Windows / Python 3.12.10 下运行 `python run_tests.py`，935 项测试全部通过，无失败、错误或跳过；`python -m c3_mass.compute_c3_mass --all` 成功生成样例计算结果。Python 语法、变更空白和新增文档链接检查通过。本轮未修改前端，也未重新执行浏览器及真实游戏验收。

## 1. 先建立持续集成与可复现验证

现有 `run_tests.py` 已隔离数据库与输出目录，前端也有 TypeScript 检查和构建入口，但缺少自动执行这些检查的 CI 配置。优先在干净的 Windows / Python 3.12 环境运行完整测试及前端构建，再逐步加入 Linux 支持。当前虚拟环境是 Windows 环境，不能直接作为 Linux 依赖环境使用。

验收：全新检出后按 README 安装即可测试；CI 使用临时数据库；失败阻止发布；生成的运行时包包含 `c3_mass/`，解压后首页、样例计算和主要 API 均可用。前端依赖用 `npm ci` 安装，构建检查在临时副本执行，避免无意改写随版本交付的 `frontend/dist/`。

## 2. 补齐校准来源与独立飞行验证

README 已说明历史校准原始记录未回填。增加公式或测试数量无法替代飞行证据。优先为现有火箭补齐 craft、游戏及模组指纹、载荷、轨道、剩余 Δv 和采样时点，再采集未参与拟合的验证点。

验收：至少在校准区间内与区间外各有独立验证点，报告预测差值和来源；界面继续区分校准范围与外推。误差结论只适用于实际验证的构型和任务范围。

## 3. 增强 SQLite / YAML 写入恢复

`server/models.py` 已有临时文件替换和异常回滚，但 SQLite 提交与 YAML 替换仍是跨介质的两个步骤。可以增加操作日志或待同步队列，以 SQLite 为主记录同步状态，启动时识别未完成操作并提供显式恢复。

验收：在 YAML 替换前后、数据库提交前后注入中断，重启后均能发现不一致；恢复操作先备份并记录覆盖方向；保留当前只读 `data_tools.py audit` 的行为。

## 4. 减少环境与发布流程中的机器依赖

`server/config.py` 仍包含本机 KSP 路径候选，部分工具和发布输出路径带固定日期。下一步可集中配置路径、在界面保存安装位置，并让发布目录由版本生成；根目录独立质量实验脚本也可在补齐专用入口后归入工具包。

验收：项目换目录或换机器后按文档配置即可运行；找不到游戏安装时明确显示所需配置；历史实验的输入哈希和证据路径保持可追溯。

## 5. 再扩展物理模型与用户体验

在证据和恢复机制稳定后，按真实使用需求选择有限推力、级寿命、并联燃烧等扩展。先明确输入、适用域和参考答案，再接入查询与结果页面。可同时复核小屏操作、批量导入失败重试和大规模火箭库查询性能。

验收：每项模型扩展都有独立参考案例；未支持的构型仍明确返回限制。新功能通过 API 与界面的实际工作流验证后才进入发布说明。
