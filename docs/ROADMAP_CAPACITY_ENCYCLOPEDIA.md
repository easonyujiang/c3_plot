# 运力百科与自动校准路线图（草案）

更新：2026-10-24。状态：规划草案，未实施。本文把“给一枚完整火箭，几次点击得到完整参数百科和几乎任意轨道的运力”拆成可执行阶段，用于先确认范围与顺序。

## 0. 目标与边界

目标：输入一枚完整火箭（craft + 游戏环境），通过少量人工点击得到：

1. 完整的火箭参数百科（级段、质量、发动机、油箱、Mod 来源、版本）；
2. 任意轨道的运力：模型估算、已实飞验证、已测试失败边界、带余量建议值；
3. 每条结论都可追溯到飞行证据或模型假设。

约束与已定决策：

- **自动校准飞行是必须的**；但测试量要最小化，允许明确标注的误差。
- **GEO 直送**暂不建模级寿命、电源/热、推进剂沉底；只建模质量、推力、比冲、点火次数和有限燃烧修正。
- **逆行/极地**允许初始发射轨道倾角不等于 90°；允许把平面变化分配到上升段、停泊轨道或远地点，不强制“直飞 90°”。
- **分级和飞行程序是设计输入**：由用户提供/批准 recipe，campaign 只执行和报告，不自动改设计。
- **AI 弱干预**：正常流程是确定性的；异常时 AI 只提议 campaign spec/程序修改，由人批准；AI 不直接控制油门、姿态或分级。
- 现有 F/G 两架次受非预期滑行影响，只能作为历史下界，不作为标准校准；新 campaign 重新飞。
- 不追求一次覆盖所有构型；先支持可无歧义识别的串联火箭，并联/复杂拓扑显式标记待审。

## 1. 能力拆分

| 能力 | 现在 | 目标 | 主要缺口 |
| --- | --- | --- | --- |
| 火箭参数 | 编辑器快照给出串联系质量、发动机、油箱、Mod 指纹 | 任意支持的 craft 自动生成完整档案 | 去 Neutron 硬编码、通用拓扑、部件级清单、版本 |
| 运力模型 | 3 点经验曲线 + 等效 C3 | 多保真仿真 + 参数目录 + 任意轨道估算 + 验证点 + 不确定度 | 仿真内核、KSP 参数目录、逆行/极地、标定/UQ |
| 校准 | 单箭/单轨道手工 harness | 通用 campaign，自动载荷/轨道搜索 | trial spec、复位、队列、失败分类 |
| 测试量 | 每架次手工准备 | 仿真引导的最少飞行 | 锚点设计、敏感性/主动学习、停止规则 |
| 交互 | CLI + AI 编排 | 几次点击的本地工作台 | 后台任务、进度、百科/运力页面 |
| AI | 当前由 AI 编排/诊断 | 正常 loop 无 AI；异常弱干预 | 异常监督、spec 提议、人工批准 |

## 2. 关键设计决策

### 2.1 多保真度仿真，而不是单一公式

- **T0 解析/脉冲**：火箭方程 + 二体/patched-conic；秒级；覆盖所有轨道；用于初始估算和反演。
- **T1 3DOF 轨迹**：RSS 重力/大气、阻力/FAR 代理、推力/Isp/节流、质量流、分级、有限燃烧、制导；用于全场容量图。
- **T2 6DOF/FAR**：姿态、气动面、控制、结构约束；用于高保真校验和边界案例；部分可用 KSP-in-the-loop 代替。
- **T3 实飞/回放**：KSP + 遥测；用于参数标定和最终验证。

原则：

- T0/T1 负责“任何轨道都有答案”；T2/T3 负责“答案是否可信”；
- 多保真校准：T1 对 T2/T3/飞行，T0 对 T1；
- 第一版不重写 FAR/6DOF；先用 3DOF + FAR 代理 + KSP 校验；
- 每层都输出不确定度，界面并列显示估算/已验证/失败边界。

### 2.2 逆行/极地：允许非 90° 初始轨道

- 输入目标倾角（如 97.8° SSO、180° 逆行），允许选择初始停泊轨道倾角；
- 在“发射方位/狗腿代价”和“停泊/远地点平面变化”之间做代价优化；
- 显式建模地球自转项（逆行时符号和大小必须用飞行校验）；
- 对 180° LEO 允许“转移远地点平面变化”或“上升段狗腿”两种方案比较；
- 锚点飞行验证 97.8° 与 180°，并记录射向/落区/狗腿限制。

### 2.3 GEO 直送：同一转移族的模板，不是独立任务类型

按“停泊轨道 → 转移点火 → 远地点圆化/平面变化”的架构，GEO 直送与
GTO + 远地点圆化属于同一冲量族；区别主要在：

- 远地点点火由上面级执行，可能是一次长燃烧；
- 是否在停泊轨道滑行/再点火；
- 目标倾角与平面变化分配。

因此：

- **默认不为 GEO 直送单独增加试验锚点**；用 GTO 锚点 + 有限燃烧/点火次数修正外推；
- 仅当任务定义是“无停泊轨道/直接上升”或点火序列与 GTO 不同，才作为 `direct_ascent` 变体单独建模/验证；
- 按已定边界忽略级寿命、电源/热、推进剂沉底；只保留质量、推力、比冲、点火次数和有限燃烧修正。

### 2.4 轨道太多：按族和参数建模，不按轨道名枚举

把目标轨道压缩成少数族 + 连续参数：

- **圆轨道**：高度、倾角（LEO/MEO/GEO；SSO 的倾角由高度决定）；
- **椭圆轨道**：近地点、远地点、倾角、近地点幅角/RAAN（GTO、Molniya、Tundra）；
- **逃逸/高能**：C3、赤纬、RAAN（TLI/行星际）；
- **特殊**：太阳同步、重复地面轨迹、定点/相位。

物理层用二体/patched-conic + 平面变化优化；经验层用响应面/GP，输入是
`r_a/r_park`、`r_p/r_park`、`Δi`、`C3/v_esc²`、TWR、级数、程序等
无量纲特征。命名轨道只是模板预设，不是独立试验对象。

- **SSTO** 是火箭构型，不是轨道族；纯火箭 SSTO 用同一模型，吸气/组合循环需要单独模型或标记不支持。
- **Molniya/Tundra** 是高偏心、特定倾角/近地点幅角的椭圆模板；GTO + 极地/逆行锚点可约束，必要时再加一个锚点。
- **TLI/行星际** 是 C3>0 的高能模板；需要高能锚点或明确标未验证。
- **各种 SSO** 是“高度决定倾角”的一参数族；一个锚点可覆盖，其他高度由模型插值。
- **MEO/倾斜同步转移** 是高度/倾角参数，不需要按每个高度单独飞。

### 2.5 测试量最小化：物理先验 + 序贯设计

不以“每个轨道都飞”为目标，采用：

1. **物理先验**给出初始运力曲面；
2. **锚点飞行**校正关键区域（见 4.1）；
3. **响应面/GP/贝叶斯**拟合载荷、轨道、倾角、程序到运力的关系；
4. **主动学习**选择信息量最大的下一架次；
5. **留出验证**：未参与拟合的轨道/载荷必须通过独立飞行；
6. 达到误差目标或边际信息量不足时停止。

**硬上限：每枚火箭最多 6 架次。** 不足的轨道族只能由模型插值并标“未验证”，不能假装全部实飞覆盖；如果 6 架次内无法达到误差目标，输出必须显式列出未探索区域，而不是硬给一个数。

同一机队内可用分层模型/迁移学习：共享发动机、油箱、级质量的型号可以少飞。

### 2.6 自动化架构

- **Campaign engine（Python，确定性）**：trial spec、队列、预算、载荷搜索、轨道矩阵、失败分类、审计、证据。
- **Game adapter（C#/kOS）**：加载模板存档副本、设置载荷/目标/程序、飞行、记录、复位/退出。
- **状态复位**：每次 trial 用独立存档副本；支持“一次一进程”（稳）和“单进程多 trial”（快）。
- **失败分类**：载荷/结构、制导、级序、点火/再点火、推进剂、电量、轨道误差、超时、游戏崩溃。
- **证据**：每个 trial 哈希绑定；campaign manifest 记录搜索范围、次数、未探索区域。

### 2.7 仿真外推 + 真实数据标定

外推底座是可执行的仿真，不是黑箱曲线：

- 仿真对任意轨道计算轨迹、Δv、容量；
- 参数来自 KSP 源文件/配置 + 飞行实验；
- 6 架次用于标定不确定参数、估计模型偏差、验证，不是拟合 6 个点。

输出任何轨道 + 置信区间；远离锚点标低置信度外推；参数不确定度、模型偏差和飞行重复性分开报告。

"完全外推"指任何轨道都能得到答案，不等于任何轨道都同等准确。

### 2.8 参数目录：KSP 源文件 + 实验

参数目录（ParameterCatalog）是仿真和百科的共同底座：

- **KSP 配置/源文件**：部件质量、资源密度、油箱容积、发动机推力/Isp 曲线、节流/点火/万向限制、drag cube/FAR 配置、RSS 大气/重力、MechJeb 制导参数；
- **运行时快照**：编辑器结算质量、级段、资源、Mod 指纹；
- **飞行实验**：速度/加速度、动压/Mach、迎角、姿态、发动机状态/节流、推进剂、级事件、电量、轨道；
- **Mod 源码/IL**：FAR、RealFuels、SSTU、SolverEngines、MechJeb 的语义与限制；必要时只读核查。

每个参数记录：值/单位、来源路径与哈希、版本、先验/不确定度、由哪次飞行识别、置信度。优先级：运行时快照 > GameData/ConfigCache > 源码 > 文献/假设；冲突显式标记，不静默覆盖。

当前遥测只有部分字段；需要补齐速度、加速度、动压、Mach、AoA、姿态和发动机状态，否则无法标定气动/制导参数。

### 2.9 标定、模型偏差与不确定度

- **参数估计**：最小二乘/贝叶斯，先验来自 KSP 源文件；飞行数据更新后验；
- **模型偏差**：用 GP/回归建模残差（仿真 vs 飞行），与参数不确定度分开；
- **验证**：留一/留出、入轨误差、容量误差、级事件、剩余 Δv、最大动压/加速度；
- **敏感性/试验设计**：哪些参数重要、哪次飞行最能降低不确定度；
- **不确定度传播**：容量置信区间、外推距离、置信等级；
- **防过拟合**：限制自由参数、保留先验、交叉验证；不能拿单次飞行拟合所有偏差。

### 2.10 AI 的角色

- 正常 loop 完全确定性，可零 AI 无人值守；
- 异常时 AI 读取遥测/日志，给出归因摘要和候选 spec 修改；
- 设计变更（分级、目标轨道、越界参数）必须人工批准；
- AI 不直接控制飞行内环；所有执行仍由确定性代码完成。

## 3. 阶段路线图

### Phase A — 数据契约、参数目录与火箭档案（无飞行）

交付：

- `RocketProfile`：craft 哈希、环境指纹、级段、质量、发动机、油箱、资源、Mod 来源、版本；
- `EnvironmentProfile` / `ParameterCatalog`：RSS 大气/重力、发动机推力/Isp 曲线、油箱容积、FAR/RealFuels/SSTU 配置、MechJeb 制导参数；每项带来源路径/哈希/先验/不确定度；
- `TrialSpec` / `TrialResult` / `CapacityPoint` / `Encyclopedia` 数据结构；
- 无校准也能保存档案；校准数据作为可选层。

验收：同一 craft 可生成稳定 profile；参数目录能追溯到 GameData/ConfigCache/运行时快照；字段缺失/不确定显式标注；schema 与来源测试通过。

### Phase B — 通用导入、百科与仿真内核 v1

交付：

- 去掉 baseline harness 对 Neutron/固定载荷/固定轨道的依赖；
- 任意可识别串联 craft 导入、参数确认、百科页面/JSON 导出；
- **T0/T1 仿真内核**：3DOF 轨迹、RSS 重力/大气、阻力/FAR 代理、推力/Isp/节流、质量流、分级、有限燃烧、基础制导；
- 仿真验证：解析解/能量守恒/时间步收敛/与 KSP 回放对比。

验收：3 枚不同 craft 导入；参数完整；T0/T1 对 220 km 基准预测与现有经验模型量级一致；未知构型不会生成假曲线；无 AI 参与。

### Phase C — Campaign v1 + 遥测升级 + 220 km 标定

交付：

- trial spec + 队列 + 模板存档复位 + KSP 生命周期；
- 遥测补齐：速度、加速度、动压、Mach、迎角、姿态、发动机状态/节流、推进剂、级事件、电量；
- 固定 recipe 下自动跑 220 km 载荷阶梯 + 载荷边界；
- 用飞行数据估计推力/Isp/质量流/上升损失等参数，并估计模型偏差；
- 自动审计、失败分类、证据冻结。

验收：一次点击后无人值守完成 220 km 校准；仿真预测与飞行在误差目标内；失败也会被正确记录；正常流程无 AI。

### Phase D — 仿真/任务族 v2（任意轨道）

交付：

- 任务求解器：圆/椭圆/转移/直送；任意高度、倾角、发射场；
- 逆行/极地：非 90° 初始轨道 + 平面变化分配 + 狗腿/射向代价；
- GEO 直送：转移族模板 + 有限燃烧/点火次数修正（不单独建任务类型；忽略级寿命/电源/热/沉底）；
- **T1 增强 + T2/FAR 代理或 KSP-in-the-loop**：用于高能、逆行、有限燃烧等边界案例；
- 参数目录与仿真联动：KSP 源文件给先验，飞行数据更新后验；
- 模型偏差层 + 不确定度；超出锚点范围明确标“未验证/低置信度”。

验收：对 220 km、SSO、GTO、GEO 0°/180°、GEO 直送给出运力与不确定度；T1 与 T2/KSP 校验在误差目标内；未验证区域不冒充实测。

### Phase E — 标定、模型偏差、UQ 与测试最小化

交付：

- 参数估计：最小二乘/贝叶斯，先验来自 KSP 源文件；
- 模型偏差：GP/回归建模仿真-飞行残差，与参数不确定度分开；
- 敏感性分析与序贯试验设计：选择最能降低不确定度的下一架次；
- 留一/留出验证、误差报告、停止规则；
- 6 架次 campaign 的锚点集、载荷策略和置信等级。

建议误差目标（可调，6 架次上限下分层）：

- **已验证锚点**：实测值，只受飞行重复性影响；
- **锚点附近估算**：`max(5%, 100 kg)`，覆盖 90% 网格；
- **远离锚点/极端轨道**（180°、GEO 直送）：`max(10%, 200 kg)`；超过则标“低置信度/未验证”，不硬给容量；
- **入轨**：近/远地点 ±5 km、倾角 ±0.2°、保持 30 s；
- 不确定度区间宽度大于目标时，要么补飞，要么降级标注。

验收：给出“试验次数–误差”曲线；每枚火箭 **≤6 架次**；满足目标后停止；未探索区域与低置信度区域显式列出。

### Phase F — 产品工作流与弱 AI

交付：

- 本地工作台：导入 → 参数百科 → 选择轨道族 → 运行 campaign → 查看运力/证据；
- 后台队列、进度、失败报告、重试/取消；
- AI 异常监督：失败归因、spec 建议、百科文本；人工批准设计变更；
- 已知 recipe 可切换“零 AI 无人值守”。

验收：一枚新火箭，几次点击得到百科与运力页；失败有明确报告；正常 loop 不依赖 AI。

### Phase G — 型号覆盖与运营

交付：

- 任务 × 火箭覆盖矩阵、能力缺口/经济性缺口；
- 版本/构型/成本/证据管理；
- 批量 campaign 与优先级排序。

验收：能解释“哪枚可用、证据是否充分、缺哪个任务能力”。

## 4. 测试与误差策略

### 4.1 锚点建议（6 架次上限）

在 6 架次上限下，不追求每个轨道族都实飞。建议的锚点族：

- 220 km 圆轨道、20°：两个载荷点（设计点 + 中载荷）；
- 220 km 圆轨道、97.8°：极地/高倾角，一个点；如果 SSO 是主要任务，把这一架换成 600 km、97.8° 的 SSO 锚点；
- 220 km 圆轨道、180°：逆行，一个点；
- GTO 220 × 35786 km、28.5°：一个点；它同时覆盖倾斜同步转移和 GEO 直送模板；
- 第 6 架次在高能/TLI（C3>0 或月球转移）与 Molniya（高偏心/63.4°）之间按任务优先级二选一；
- GEO 180°、其他 MEO/SSO 高度、Tundra 等由模型插值，明确标未验证。

**GEO 直送不单独占架次**：按“停泊轨道 + 两次点火”的架构，它由 GTO 锚点 + 有限燃烧/点火次数修正外推；只有“无停泊轨道/直接上升”变体才需要单独验证。

SSTO 是火箭构型，不是轨道锚点；纯火箭 SSTO 用同一套 6 架次框架，吸气/组合循环单独标记。

### 4.2 单箭试验预算：6 架次示例

以“220 km、20°、5 t”这枚火箭为例，初始计划如下：

| # | 目标轨道 | 载荷 | 目的 |
| ---: | --- | ---: | --- |
| 1 | 220 × 220 km，20° | **5.0 t** | 验证设计点；高载荷端锚点 |
| 2 | 220 × 220 km，20° | **2.5 t** | 分离载荷斜率与固定上升损失；第二个参考点 |
| 3 | 220 × 220 km，97.8°（SSO 为主时改为 600 km SSO） | **3.5 t** | 极地/高倾角、发射方位与平面变化锚点 |
| 4 | 220 × 220 km，180° | **2.0 t** | 逆行、地球自转与平面变化锚点 |
| 5 | GTO 220 × 35786 km，28.5° | **2.5 t** | 高能/倾斜同步转移；GEO 直送模板的校准 |
| 6 | TLI（C3≈-2）**或** Molniya（500 × 40000 km，63.4°） | **1.5 t** | 高能逃逸 **或** 高偏心/临界倾角，按任务优先级二选一 |

载荷不是硬编码：第 3–6 架次取仿真预测容量的 50–70%，优先保证成功并拿到剩余 Δv；第 1 架次按设计值 5.0 t，第 2 架次取 50%。如果仿真估计某锚点明显低于该值，先按估计值下调。每个架次先离线仿真预飞，再决定是否真飞。

每架次必须记录足够的标定信号：速度、加速度、动压/Mach、迎角、姿态、发动机状态/节流、推进剂、级事件、电量。当前 CSV 只有部分字段；遥测补齐是 Phase C 的前置条件，否则气动/制导参数不可辨识。

每次飞行约束的模型项：

| 架次 | 主要标定/验证的仿真参数 |
| ---: | --- |
| 1 | 设计点；推力/Isp/质量流/节流/上升损失（低 TWR 端） |
| 2 | 载荷斜率；质量流/上升损失（高 TWR 端） |
| 3 | 气动/制导/平面变化/发射方位（高倾角） |
| 4 | 地球自转/平面变化/狗腿（逆行极端） |
| 5 | 上面级有限燃烧/点火/高能（GTO/GEO 直送模板） |
| 6 | 高 C3 **或** 高偏心/近地点幅角；模型偏差 |

**为什么 6 次就能外推**：不是用 6 个点拟合任意轨道，而是用 6 次观测标定仿真参数和模型偏差；仿真对任意轨道计算轨迹/Δv，数据只更新参数和偏差。黑箱曲线不能这样外推。

用**留一交叉验证**（每次留一架次，拟合其余 5 架，预测留出架次）估计外推误差，不额外占用飞行。若 LOO 误差在目标内，模型可用于整个参数空间；超出则降低置信度并标外推。

失败处理：

- 失败不是“重飞到成功”，而是一个**上界**；记录后由 campaign 重新分配剩余架次；
- 第 1 架次失败时，优先用一架次验证较低载荷的基准点，可能牺牲一个轨道锚点；
- 任何一次失败都要保留证据，不把上界当容量。

6 架次无法同时实飞验证所有轨道族；百科必须并列显示“已验证 / 估算 / 失败边界 / 未验证”。**轨道族覆盖靠模型 + 6 个锚点，不靠枚举轨道名。**

### 4.3 误差与状态

每个 `CapacityPoint` 记录：

- 估算值、置信区间、验证状态（已验证/估算/低置信度外推/失败/不可行）；
- 试验 spec、证据哈希、飞行次数；
- 到最近锚点的特征距离、外推方向、禁止外推条件。

**“完全外推”指任何轨道都能返回一个数和置信区间，不是任何轨道都同等准确。** 用户查询任何轨道都应得到结果；靠近锚点标“估算”，远离锚点标“低置信度外推”，只有锚点本身标“已验证”。

## 5. 数据模型（草案）

- `RocketProfile`：craft/环境指纹、级段、发动机、油箱、资源、Mod、版本、来源。
- `EnvironmentProfile`：RSS 大气/重力、发射场、游戏/Mod 版本与哈希。
- `ParameterCatalog`：参数值/单位/来源/哈希/先验/不确定度/由哪次飞行识别/置信度。
- `TrialSpec`：火箭版本、载荷、目标轨道、发射场/时间、程序 recipe、容差、预算。
- `TrialResult`：遥测、快照、审计状态、失败码、证据哈希。
- `SimulationRun` / `CalibrationResult`：仿真配置、参数后验、模型偏差、验证指标。
- `CapacityPoint`：轨道、载荷、估算/验证、置信区间、证据。
- `Encyclopedia`：profile + 参数 + 运力表 + 证据 + 缺口。

## 6. 主要风险

- **仿真保真度**：T1/T2 与 KSP/FAR 的差异可能很大；用 KSP-in-the-loop/实飞校验，不能把仿真当真值。
- **参数来源**：KSP 源文件/配置与运行时行为可能不一致；每个参数要保留来源/哈希/冲突标记，必要时只读 IL/源码核查。
- **模型外推**：逆行/GEO 直送/高 C3 的误差可能大；用锚点+LOO/留出验证，不做无依据外推。
- **程序/分级变化**：同一火箭不同 recipe 的运力不同；recipe 必须进入 spec 和指纹。
- **KSP 生命周期**：崩溃、加载慢、存档锁；需要超时、重试、模板副本、进程隔离。
- **测试成本**：每次飞行约 7 分钟 + 加载；必须靠仿真/敏感性分析减少次数。
- **计算成本**：6DOF/FAR/GP 可能很慢；T0/T1 负责全场，T2/T3 只用于关键点。
- **AI 非确定性**：只允许改 spec 并留痕；内环保持确定性。

## 7. 建议的第一阶段

先做 **Phase A**（数据契约 + 参数目录）、**Phase B**（通用档案/百科 + T0/T1 仿真内核）和 **Phase C**（单箭 220 km campaign + 遥测升级）。这三块完成后，产品已经能：

- 给一枚新火箭生成完整参数百科；
- 用 KSP 源文件 + 飞行数据标定 3DOF 仿真；
- 用少量点击跑通自动校准并冻结证据；
- 为后续任意轨道仿真/验证提供稳定数据契约。

然后再进入 **Phase D/E**（逆行/GEO 直送/测试最小化）和 **Phase F**（一键 UI/弱 AI）。

这个顺序避免在数据契约和 campaign 还不稳时，过早堆模型和 UI。
