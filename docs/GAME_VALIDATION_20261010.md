# 游戏内采样链路验收（2026-10-10）

已在实际 KSP 安装中成功回放独立存档副本，取得真实在轨飞船采样，并验证部件质量汇总与轨道能量。此验收证明采样链路可用，不代表当前 Neutron 运力曲线已经通过独立飞行验证。

## 实际完成的操作

1. 只读盘点 `saves/RocketMaking` 下 11 个 SFS 文件。找到 `quicksave.sfs` 的 `1T_Test` 在轨快照；其上面级是 LMAE 单发布局，与当前曲线的 LR81 三发布局不同，因此不作为当前曲线校准点。
2. 将原存档复制至新目录 `saves/C3MassValidation20261010`。原目录 78 个文件逐一记录 SHA-256，回放后逐一核对，全部未变。
3. 编译和安装独立回放工具 `C3MassValidation`。它只在一次性请求文件存在且独立副本哈希匹配时运行；不控制油门、分级或轨道。没有请求文件时不自动加载任何存档。
4. 首次回放因场景切换重置活动索引，选中了小行星。原始日志保留在 `replay/attempt-001`；这次不算目标飞船验收成功。随后改为在加载前按唯一船名锁定索引，并在飞行场景再次检查船名。
5. 第二次回放成功聚焦 `1T_Test`，采样约 30 秒后正常退出。结果和采样保存于 `output/curve_accuracy_20261010/replay/attempt-002`。

回放入口的场景切换方式参考了 [AutoLoadGame 原作者源码](https://github.com/allista/AutoLoadGame/blob/master/AutoLoadGame.cs)，但本工具增加了固定独立目录、来源哈希和目标船名核验，没有使用原插件的自动覆盖存档操作。游戏方法签名另用本地程序集的只读元数据反射确认，未在检查程序中执行游戏方法。

## 由真实运行发现并修正的问题

KSP 的 `ConfigNode.Save` 写出节点内容时省略最外层节点名。之前的合成样本保留外层名称，未覆盖此行为；日志分析工具现支持实际平铺格式和显式包装格式，并增加针对性测试。实际会话已通过质量与能量审计，报告为 `attempt-002/telemetry-audit.json`。

游戏仍出现大量 Unity 分配警告，但两次回放均进入飞行并按时正常退出。原先的启动日志不足以把这些警告判作无法运行的故障；完整日志保留，监视器限制运行时间与日志体积。

## 游戏启动后的来源刷新

ModuleManager 启动后把补丁缓存指纹从 `15c6d8dd…` 更新为 `400c8f04…`。重新从实际缓存导出至 `neutron_i_2630_after_game`，与启动前的完整曲线 JSON 比较，计算值完全一致。正式数据库中的发动机来源指纹已刷新，刷新前另存完整备份 `before_runtime_provenance_refresh`；SQL/YAML 审计仍 matching。

旧 RealChute 实验只授权了原缓存指纹，因此其生产估算正确保持 unresolved，没有重新授权或扩大旧证据范围。几项依赖真实安装的历史测试此前无条件期待原测量值，现按实际指纹区分：匹配时验证原测量，不匹配时验证拒绝估算及 `realchute_fingerprint_mismatch` 诊断。针对性 7 项检查通过；最新全套 918 项测试全部通过，结果保存于 `tests-runtime-final-verified.txt`。这一改变不能视为旧实验证据在新环境重新有效。
